## Critical-Thinking & Verification

AI tools significantly accelerated code implementation, spec drafting, and test generation. However, human critical-thinking and verification were essential:

- **Specification Alignment:** I cross-referenced AI-generated status transition matrices and resolution gate rules directly against `docs/lab-04/specification.md` to ensure business logic strictness. The AI initially suggested allowing RESOLVED → CLOSED transitions without checking follow-ups, which violated BR-09. I caught this during spec review and corrected the implementation.

- **Security & Authorization:** I verified that authorization checks are performed on the backend Express server using authenticated JWT session tokens rather than trusting client-supplied parameters. When the AI generated dashboard endpoints, I manually tested with Postman using different user sessions to confirm 403 Forbidden responses for cross-user access attempts.

- **Parallel Test Safety:** I refined metric assertions in server integration tests to handle concurrent Vitest database mutations safely. The AI's initial dashboard tests assumed isolated test data, but parallel execution caused race conditions. I added transaction isolation and cleanup hooks to ensure tests don't interfere with each other.

- **Follow-Up Logic Correctness:** When implementing resolution blocking (BR-09), the AI initially checked if ANY action had `followUpRequired=true` but didn't verify the action was still incomplete. I corrected this to check that follow-ups exist AND are unresolved, preventing false positives when staff mark follow-ups complete.

- **Accessibility Compliance:** The AI generated focus outlines, but I manually tested with NVDA screen reader and keyboard-only navigation to verify actual usability. I discovered the Dashboard navigation link was missing from AppShell (required by ui-spec.md Section 2.1) — the AI had overlooked this requirement. I added the link and verified with screen reader.

- **Date Boundary Testing:** For dashboard metrics filtering by "last 7 days" and "last 30 days," I manually tested edge cases (tickets updated exactly 7 days ago, timezone boundaries, midnight crossings) that the AI's tests didn't cover. I found timezone inconsistencies and added explicit UTC date handling.

- **Responsive Layout Verification:** While the AI generated responsive CSS breakpoints, I manually resized the browser to exact widths (375px, 768px, 1280px) and tested on a physical mobile device (iPhone 13) to verify no horizontal scroll, no overlapping elements, and proper touch target sizes. I found one card layout bug at 768px that the AI's automated tests missed.

- **Test Plan Traceability:** I manually verified that every Acceptance Criterion (AC-01 through AC-36) in `specification.md` had corresponding test coverage in `tests.md`. The AI generated tests but didn't maintain the AC-to-Test traceability matrix. I cross-checked and documented missing coverage gaps (UI-01 through UI-12 initially had no implementations).

- **Database Migration Safety:** Before applying Prisma migrations, I reviewed the generated SQL to ensure no data loss, proper foreign key constraints, and correct index creation. The AI generated a migration that would have cascaded deletes on ActionsTaken when a User was deleted, potentially losing audit trail. I changed it to a soft-delete pattern with `onDelete: Restrict`.

- **Error Message Quality:** The AI generated generic error messages ("Validation failed"). I refined them to be actionable and specific ("Resolution blocked: 2 incomplete follow-up actions remain. Complete actions #47 and #52 before resolving."). This required understanding user needs beyond what the AI inferred from requirements.
